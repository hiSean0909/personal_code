# intent.md — 20261013_personal_assistant

## 意图

在本地实现一个个人助手：启动一个可对话的聊天窗口，背后调用大模型。按「AI Native」思想开发——**大模型是应用的引擎，代码只是薄薄的外壳**，产品逻辑用自然语言（提示词）定义，而不是硬编码规则。

## 目标

1. **对话式界面**：启动后打开本地网页对话框，像日常聊天一样连续对话（多轮上下文）。
2. **大模型驱动**：所有「智能」来自 LLM（DeepSeek，OpenAI 兼容接口），代码里不写任何意图判断 / if-else 业务规则。
3. **AI Native 设计落地**：
   - **提示词即产品**：助手的角色、风格、能力边界全部写在提示词文件里，改提示词 = 改产品，不用动代码
   - **上下文即状态**：会话历史是应用唯一的核心状态，每轮组装后整体交给模型
   - **模型即引擎**：模型与接口全部用环境变量配置，换模型零代码改动
   - **自然语言即界面**：聊天框 + 流式输出（打字机效果），对话优先

## 非目标

- 不做工具调用、RAG、跨会话记忆持久化（后续项目再练）
- 不做多用户、鉴权、云端部署
- 不做传统软件的功能堆叠（待办、日程等硬编码功能）

## 已确认的关键决策

| 决策项 | 选择 |
|---|---|
| LLM | DeepSeek API（deepseek-chat，OpenAI 兼容接口） |
| 界面 | Gradio Web 对话框（流式输出） |
| 多轮记忆 | 会话内多轮上下文（窗口截断），不做跨会话持久化 |
| 产品逻辑载体 | 系统提示词文件（personal_assistant_prompts.md，与代码分离） |

## 成功标准

- 启动后可在网页中连续对话，模型能理解上下文（如「我刚才说的第一句话是什么」）
- 回复流式逐字呈现，体验接近主流 AI 对话产品
- 只改提示词文件即可改变助手人设，代码零改动

## 约束

- Windows 环境，Python 3.10+
- 需要环境变量 DEEPSEEK_API_KEY
- 遵循 my_practice 原则：独立实现、优先跑通、代码保持精简
